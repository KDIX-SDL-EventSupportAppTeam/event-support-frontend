# 評価モーダル（P0 — 最優先）

**これは UX 改善ではない。理論の成立条件である。**

評価の回収率が DRSA 決定表の件数を決め、決定表の件数が使える条件属性の個数を決める。今年の総チェックインは 900〜1,200件、回収率が去年並み（36.4%）なら評価は約364件しか集まらない。条件属性3個×3値で13.5件/パターン、4個で4.5件/パターンが境界である。**回収率が上がらなければ推薦手法そのものが成立しない。**

## 設計

**独立した評価画面を作らない。チェックイン成功モーダルの先頭ステップに組み込む。**

「後で評価してね」に依存すると回収率は3割を切る。次のブースで QR を読んだ瞬間に、**前のブースの評価を1タップで聞く**。行動の流れに埋め込まれるため回収率が跳ね上がり、記憶も新しい。

## フロー

```
QR読み取り / 手動コード入力
      ↓
POST /checkins  →  レスポンスに pending_rating
      ↓
┌─────────────────────────────┐
│ ステップ1: 前ブースの評価      │ ← pending_rating が非 null のときのみ
│ 「○○」はいかがでしたか？      │
│  [☆][☆][☆]   [スキップ]     │
└─────────────────────────────┘
      ↓ 送信 or スキップ
┌─────────────────────────────┐
│ ステップ2: チェックイン成功    │
│  ブース名 / 埋まったマス       │
│  （解放時はここで解放演出へ）  │
└─────────────────────────────┘
```

- **評価をデフォルトで前面に出す。**スキップ可能にするが、スキップを目立たせない
- 評価は `POST /checkins/:checkin_id/rating` に `context: 'NEXT_CHECKIN'` で送る
- 評価の送信失敗でチェックインの成功表示を妨げない。**評価は失敗しても握りつぶしてよい**（次回のチェックインで再度 `pending_rating` として出てくる）

## 既存実装との差分

`src/features/checkin/pages/CheckInPage.tsx` の `step` は現在 `booth` → チェックイン → 評価 → 推薦 の順になっている。

- **評価ステップをチェックイン成功表示の「前」に移す**
- 評価対象を「今チェックインしたブース」から **`pending_rating` が指すブース**に変える。これが最大の変更点である
- `CheckInRatingModal` の props に `boothName` は既にある。**段階数を `ratingScale` として受け取る**ようにする

## 段階数

**ハードコードしない。**`GET /bingo/card` の `rating_scale`（既定 3）に従って星の数を変える。

現在の `CheckInRatingModal` は `[1,2,3,4,5].map(...)` で5個固定になっている。`Array.from({length: ratingScale})` に置き換える。文言の「5段階で評価してください」も動的にする。

3段階になる見込みの理由: ブース関係者が目の前にいる状況では1〜2が押されず、5段階は実質4と5の2値になる。ただし**最終決定はまだ**（[Q-F2](../06-open-questions/open-questions.md)）。

## 取り逃す1件

最後に訪問したブースの評価は、構造上チェックインモーダルでは聞けない。
**マスのタップから手動で評価できる導線を用意する**（`context: 'MANUAL'`。[reason-text.md](../02-bingo-card/reason-text.md)）。
