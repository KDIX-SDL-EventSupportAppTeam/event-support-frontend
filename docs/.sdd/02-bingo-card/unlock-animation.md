# 解放演出

**この瞬間が本設計における最大の報酬体験である。**中央2x2 はラインを構成しないためコインは出ない。報酬は「12マスが開くこと」そのものである。

## トリガー

**正の経路:** `POST /checkins` のレスポンス `unlocked === true`。
**副経路:** socket.io の `bingo:unlocked`（room: `event:{event_id}:user:{user_id}`）。取りこぼし対策。

**両方が届いても演出は1回だけ。**「このカードの解放演出を再生済みか」をローカルに持つ（`card_id` をキーに `sessionStorage`）。ページをリロードしても再生し直さない。

## 要件

- 外側12マスが**開く**アニメーション。中央から外側へ広がる形が自然
- 簡素でよい。ただし**必ず「開いた」ことが分かる**こと
- 演出中に操作をブロックしすぎない。スキップできること
- 演出後にカードを再取得し、12マスのブース名を表示する

## やってはいけないこと

- **楽観的に演出を出さない。**解放はサーバー側の処理である。「中央3件埋まったからそろそろだろう」でアニメーションを始めてはならない。オフライン中は解放が起きない（[04-offline](../04-offline/offline-queue.md)）
- **コイン獲得の演出と混ぜない。**この時点でコインは増えていない
- 「おめでとう、○○ラインです」のような、成立していないラインを示唆する文言を出さない
