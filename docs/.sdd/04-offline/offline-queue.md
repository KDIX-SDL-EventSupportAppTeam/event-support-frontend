# PWA オフラインキューと段階解放

会場の WiFi が不安定なため、チェックインはオフラインキューに積んで復帰時に送信する既存方式を**維持する**。

## 段階解放との関係（重要）

**解放はサーバー側の処理である。オフライン中に3件目のチェックインが発生しても、オンライン復帰まで解放は起こらない。**

→ **フロントは楽観的に解放演出を出してはならない。**
→ サーバーから `unlocked: true` を受け取ってから演出する。

同様に、以下もローカルで先回りして計算しない。

| 値 | 理由 |
|---|---|
| どのマスが埋まるか | 中央マスの割当はサーバーが `position` 昇順で決める。競合時の再試行もサーバー側 |
| 外側12マスの中身 | 推薦サービスの結果。フロントには知りようがない |
| コイン枚数 | サーバーが再計算した値を正とする |
| 解放したかどうか | 条件付き UPDATE を取れたリクエストだけが解放する |

## キューの flush

- 複数件がまとめて送信される。**サーバーは `checked_in_at` の差でクールタイムを判定する**ため、正当な間隔の複数件は弾かれない
- 3件目で解放が起きた場合、`unlocked: true` は**その1件のレスポンスにだけ**立つ。flush 処理は各レスポンスを見て、**最初に `unlocked: true` を見つけた時点で演出を予約する**
- flush 完了後にカードを1回だけ再取得する。1件ごとに再取得しない

## オフライン中の表示

- カードは最後に取得した状態をそのまま表示する
- 「あと N ブース」のガイドも最後の値のまま。**ローカルで減算しない**
- 未送信件数が分かるインジケータを出す（既存方式を踏襲）
- オフライン中にロック中マスの中身を推測して表示することは当然ない

## 評価の扱い

評価もオフラインキューに乗せてよい。ただし**評価の送信失敗はユーザーに見せない**。次のチェックインで `pending_rating` として再度出てくるため、実害がない。
