# ADR 0005: アイコン素材を「正方形キャンバスに絵柄が一杯」へ正規化する

- **日付:** 2026-09-07
- **ステータス:** 採用

## 状況

2026-09-06 にアート担当から「修正版」一式を受領し、既存素材 16 点を差し替えた。
その反映作業で、以前から抱えていた次の問題が表面化した。

**素材ごとに透明余白の量がばらばらで、同じ CSS 寸法を与えても見た目の大きさが揃わない。**
受領時点の各素材について、キャンバスに対して絵柄が占める割合を測ると次のとおりだった。

| 素材 | キャンバス | 絵柄の占有率 |
|---|---|---|
| `icon/nav/nav-home.png` | 400x300 | 0.34 x 0.58 |
| `icon/nav/nav-schedule.png` | 1254x1254 | 0.65 x 0.72 |
| `icon/nav/nav-fab-checkin.png`（新） | 1254x1254 | 0.96 x 0.97 |
| `icon/status/warning.png` | 1024x1024 | 0.79 x 0.53 |
| `icon/action/menu.png` | 1536x1024 | 0.63 x 0.54 |

ボトムナビは `max-height: 2.3rem` だけで寸法を決めていたため、この占有率の差が
そのまま見た目の大小になっていた。とくに新しい `nav-fab-checkin.png`（占有率 0.96）と
旧 `nav-home.png`（0.34）が隣り合うと差が目立つ。

もう一つ、素材によってラベル文字が絵に焼き込まれていたりいなかったりして、
ボトムナビでは「焼き込みラベルの項目」と「HTML でラベルを出す項目」が混在していた。
文字サイズも位置も揃わない。

## 決定

1. **`public/icon/**` の素材はすべて、透明余白を切り落とした正方形キャンバスに、
   上下左右 4% の余白を付けて絵柄を中央配置する。** 占有率はどれも 0.85〜0.93 に収まる。
   例外は `icon/nav/nav-set-home-checkin-guide.png`（3 項目が横に並ぶ合成画像）だけ。
2. **UI 側は固定の正方形ボックス＋`object-fit: contain` で描く。**
   `max-height` だけの指定はしない。
3. **ボトムナビでラベル文字が焼き込まれた素材を使うのは中央 FAB だけにする。**
   側の 4 項目は文字なしのグリフに揃え、ラベルは `showLabel` で HTML 側に出す。
   ホーム / 参加ガイドのグリフは、受領した合成画像から焼き込みラベルを除いて切り出した。

## 結果

- ボトムナビのアイコン寸法は `--pf-nav-icon-size`（1.9rem）と `--pf-nav-fab-size`（3.2rem）の
  2 つだけで決まる。素材を差し替えても見た目の大きさは変わらない
- オンボーディングの機能アイコン（3rem 角）とスワイプ説明も同じ大きさに揃った
- 注意事項画面の警告アイコンが 96px のボックスを埋めるようになった
- 新素材が余白なしで支給されるようになったため、`.pf-logo` が持っていた
  `object-fit` / `object-position` による余白切り落としのハックを削除できた
- **代償:** 素材はアート担当から受領したままのバイナリではなくなる。再受領のたびに
  同じ正規化をかけ直す必要がある（手順は [reference/assets.md](../../reference/assets.md)）

## 代替案（却下理由）

- **CSS で素材ごとに `transform: scale()` を当てて補正する** — 素材の枚数だけ係数が増え、
  差し替えのたびに再計測が要る。`.pf-logo` で同じことをやって実際に破綻しかけた
- **素材をそのまま使い、見た目の不揃いを許容する** — ボトムナビは常時表示で、
  不揃いが最も目に付く場所だった
- **アート担当に余白なしでの再支給を依頼する** — ロゴについては実際に依頼して解決した。
  ただし全素材に同じ精度を求めるのは現実的でなく、受け取り側で正規化するほうが確実
