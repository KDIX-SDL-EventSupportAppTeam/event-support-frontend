# ADR 0004: 参加者の入口を配布 URL 1 本に統合し、状態機械にする

- **日付:** 2026-08-28
- **ステータス:** 採用

## 状況

参加者がアプリ本体に到達する経路が 3 本あった。

| 経路 | 入口 |
|---|---|
| 事前アンケート | `/pre-survey/:eventId` → `signup` / `signin` → `form` → `thanks` |
| 新規登録とメール確認 | `/register` ・ `/join/:eventId` → `/verify-email/sent` → `/verify-email` |
| ログイン | `/login` → `resolveLandingPath` → `/onboarding` |

3 本が独立していたため、次の破れが生じていた。

- オンボーディング判定（`resolveLandingPath`）が `LoginPage` にしか無く、
  **登録 → メール確認 → ホームで入った利用者は一度も通らない**
- メール確認が `/verify-email/sent` で本線を切り、**アンケートを飛ばして本体に着く**
- 既読が localStorage のため、回答（自宅の PC）と入場（当日のスマホ）で端末が変わると毎回出る
- 事前アンケートは**メールアドレスと推薦用の属性を取る唯一の手段**であり、迂回路があってはならない

導線の大半は「回答完了から開放時刻まで」の待ち時間（数日〜数週間）が占める。
この間にセッションは切れ、端末も変わる。**どこで中断しても再開できること**が要件になる。

## 決定

参加者が触る URL を `/e/:eventId` 1 本に統合し、**URL は段階を持たず、サーバーが持つ**構成にする。

- 踏むたびに `GET /events/:event_id/me/state` を 1 回呼び、戻り値だけで表示を決める
  （判定は `features/entry/lib/resolveEntryStep.ts` の純粋関数に集約）
- 段階は S1 サインイン / S2 メール確認 / S3 アンケート / S4 開放待ち / S5 オンボーディング
- オンボーディング既読はサーバー（`users.onboarding_completed_at`）に持つ。localStorage は使わない
- メール確認はサインアップ直後に置く（未確認のまま属性を集めない）
- 出展者・運営はアンケート導線に乗せず、そのままアプリ本体へ通す
- 旧 URL（`/login` ・ `/register` ・ `/join/:eventId` ・ `/pre-survey/*` ・ `/onboarding`）は
  **リダイレクトとして残す。** 配布済み・ブックマーク済みの URL を 404 にしない
- 未認証リダイレクトと `*` の落下先は、直近に踏んだ `eventId`（localStorage）を使って配布リンクへ戻す

URL 名を `/pre-survey/` から `/e/` に変えたのは、この URL がログインもオンボーディングも兼ねて
実態と合わなくなるため、および QR に刷るため短さが効くため。

## 結果

- 中断復帰が設計として保証される。S2 で離脱しても、翌日同じリンクを踏めば S2 から再開する
- 端末が変わっても状態が保たれる（サーバーが持つため）
- アンケートに迂回路が無くなり、属性データの取得漏れが起きない
- 参加者向けの独立ルートが消え、導線の分岐が 1 つの純粋関数に集約される
- **ADR 0002 を一部置き換える。** 同 ADR は参加者ルート（`/login` ・ `/register` ・ `/join/:eventId`）を
  「ルートとして存続させる」としていたが、リダイレクトに変更した。
  同 ADR が懸念した「配布済み QR が 404 になる」問題は、リダイレクトで残すことで回避している。
  トップ `/` を `/organizer/login` に送る決定自体は維持する

## 代替案（却下理由）

- **段階ごとに URL を持ったまま、遷移だけ直す:** どの画面からも「次はどこか」を判断する必要があり、
  判定が各ページへ散る。中断復帰も URL の当て推量になる — 却下
- **既読を localStorage に置いたまま単一 URL にする:** 端末が変わると判定が崩れ、
  単一 URL の利点（どこからでも再開できる）が成立しない — 却下
- **当日飛び込み用に `/register` を残す:** アンケートを飛ばす経路になり、
  推薦システムが必要とする属性が欠けた参加者が生まれる — 却下
