# ADR 0002: トップ `/` をオーガナイザーログインにリダイレクトする

- **日付:** 2026-07-01
- **ステータス:** 採用

## 状況

デプロイ後の本番 URL（`/`）を開くと、参加者向けランディング（`LandingPage`: ロゴ +「新規登録」`/register` +「ログイン」`/login`）が表示されていた。
運用上の主たる入口をイベント作成者（オーガナイザー）にしたいという要望が出た。

参加者はトップから入るのではなく、**イベント個別の QR / リンク（`/join/:eventId`）から参加する**運用とする。チェックイン・投票・ガチャポン等の参加者向け中核機能は、引き続き本番で動作している必要がある。

## 決定

- `router/index.tsx` のトップルートを `<Route path="/" element={<Navigate to="/organizer/login" replace />} />` に変更し、`/` アクセス時に `/organizer/login` へリダイレクトする
- 参照されなくなった `features/auth/pages/LandingPage/` を削除する
- 参加者の登録・ログイン経路（`/login`・`/register`・`/join/:eventId`）は**ルートとして存続**させる。直接 URL や QR からは引き続き到達可能とし、塞がない

## 結果

- 本番トップを開くとオーガナイザーログイン（`/organizer/login`）に着地する
- 参加者は `/join/:eventId`（QR / リンク）から登録し `/home` へ進む。**参加者向け中核機能には影響しない**
- 未知パスの catch-all（`*` → `/`）も `/organizer/login` に着地する（トップ＝オーガナイザー方針と一致）
- 未使用だった `LandingPage` を削除し、デッドコードを解消した

## 代替案（却下理由）

- **参加者ルートごと削除 / 遮断:** チェックイン・投票等の中核機能が本番で使えなくなり、配布済み QR（`/join/:eventId`）も 404 になる。イベント本番前の再開漏れリスクも高い。将来塞ぐ必要が生じた場合は、`ORGANIZER_SIGNUP_MODE` と同様に **env フラグで可逆に切り替える方式**で行う — 却下
- **`/` をオーガナイザー / 参加者の選択画面にする:** 現フェーズはオーガナイザー主導の入口で足りるため不要。必要になれば再検討 — 却下
