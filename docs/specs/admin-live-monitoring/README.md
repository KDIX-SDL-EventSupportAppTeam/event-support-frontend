# 運営ダッシュボードの当日監視ブロック

**当日、推薦が壊れていないかを見るための画面。**
サーバーは既に必要な値を返しているが、**画面が描画していない。**

> 評価回収率は、推薦手法が成立するかを左右する最重要指標である。
> それが当日見えないまま本番を迎えることは、この画面が無いのと同じである。

## API 契約は server が正本

- ダッシュボード集計: `event-support-server/docs/specs/recommender-phase-linkage/02-dashboard-and-contract.md`
- フェーズの中継: `event-support-server/docs/specs/recommender-phase-linkage/01-ops-state-relay.md`

**内容をコピーしない。値を作らない。サーバーが返した値をそのまま出す。**

## 画面に出すもの

`/admin/dashboard` の既存カードの下に、**当日監視**のブロックを1つ足す。

### 1行目 — 評価回収率（最も大きく出す）

| 表示 | 出どころ |
|---|---|
| 評価回収率 | `bingo.rating_collection_rate` |
| 評価数 / チェックイン数 | `bingo.ratings` / `bingo.checkins` |

**この画面で最も目立つ位置に置く。** 他の指標より大きく表示する。

### 2行目 — 推薦エンジンの状態

`GET /admin/events/:event_id/recommender/state` の結果を出す。

| 表示 | 出どころ |
|---|---|
| 現在のフェーズ | `state.phase.current` |
| 決定表の件数 | `state.snapshot.decision_table_size` |
| 次のしきい値までの残り | `state.config.phase_*_min` と決定表件数から**表示のためだけに引き算する** |
| 品質ゲートの内訳 | `state.phase.gate_detail` の4項目（size / rules / gamma / coverage）を ○× で |
| 最終取り込み時刻 | `state.snapshot.built_at` |

**`available: false` のときは、数字を出さずに理由を出す。**

| `reason` | 画面の文言 |
|---|---|
| `UNCONFIGURED` | 「推薦エンジンが未設定です」 |
| `UNAUTHORIZED` | 「推薦エンジンの認証に失敗しています（設定の問題）」 |
| `UNREACHABLE` | 「推薦エンジンに接続できません」 |
| `BAD_RESPONSE` | 「推薦エンジンの応答が読めません」 |

**「取得不能」を空欄や 0 で表現しない。** 当日、値が 0 なのか取れていないのか区別できなくなる。

### 3行目 — 解放とフォールバック

| 表示 | 出どころ |
|---|---|
| 解放到達人数（1回目 / 2回目 / 3回目） | `bingo.unlocks.first / second / third` |
| 直近30分のフォールバック率 | `bingo.fallback_rate_last_30min` |

フォールバック率は**高いほど異常**である。しきい値を超えたら色を変える（既存の配色トークンを使う）。

## 2つの「件数」を混同させない

同じ画面に、意味の違う件数が2つ出る。**並べて出し、違いが分かる表記にする。**

| 表示名 | 出どころ | 意味 |
|---|---|---|
| 評価数 | `bingo.ratings` | **今この瞬間**の DB の事実 |
| 決定表の件数 | `state.snapshot.decision_table_size` | 推薦エンジンが**最後に取り込めた**件数（最大5分古い） |

差があるのは正常である（取り込み待ち）。**差があること自体を隠さない。**

## 更新

  他の集計は今までどおり表示し続ける
