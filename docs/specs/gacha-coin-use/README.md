# ガチャコイン使用画面（複数枚）

根拠: issue #150。API 契約の正本は
`event-support-server/docs/specs/gacha-and-award/03-coin-lifecycle/spending.md` と
同 `04-api/`。**サーバーの API は変えない。**

## 何を変えたのか

**1枚ずつしか使えなかったのを、枚数指定にする。** 上限4枚では使用確認画面を4回通ることになり、
筐体の前で複数回回す参加者が待たされる。

## 枚数の指定

- **ステッパー（`− n ＋`）。手動入力（テンキー・金額入力風）は採らない。**
  上限4枚では桁を意識させる意味が無く、入力ミスの余地を増やすだけである
- 範囲は `1` 〜 **`coins.available`（サーバーが返した値）**。
  `MAX_GACHAPON_COINS` をこの画面の上限判定に使わない
- `available` が1枚のときはステッパーを出さない（従来どおりの1枚フロー）
- 選んだ枚数ぶんのコイン画像を濃く出す。所持枚数そのものは減らして見せない

## 確認

- **確認は1段のみ。** 二重確認モーダルを重ねない（押し慣れて無意味になる）
- ボタンのラベルに枚数を出す（`2枚使う`）
- **「使用後は取り消せません」を確認画面に明記する**
- 押下直後に `disabled`、ラベルを「使用中…」に変える

## 呼び方（逐次・冪等キーは枚数ぶん）

| 決まり | 理由 |
|---|---|
| 既存の**1枚消費エンドポイントを枚数ぶん順番に呼ぶ** | 台帳方式（1枚 = 1行）。まとめて INSERT する形にすると `HAVING` と `coin_index` の設計をやり直すことになる |
| **並行に投げない** | `coin_index` の競合で無駄な再試行が増える |
| 冪等キーは**1枚につき1個の UUID** | **サーバーが UUID 形式で検証する**（形式違反は 400 `INVALID_BODY`）。`<操作ID>:<通し番号>` のような派生キーは送れない |
| キー列は**画面の状態として保持する** | 同じ枚数での再試行で**同じキー列**を送れる。途中で通信エラーになっても枚数が増えない |
| **枚数を変えたらキー列を作り直す** | 別の操作として扱う。前の枚数のキーを流用すると成立済み扱いになる |

## 部分成功を正直に見せる

**「全部か無か」にはできない。** 使用は取り消せず、ロールバック手段が無いため、
成立した分を取り消してはならない（救済は運営が `bonus_coins` を +1 する運用）。

| 結果 | 表示 |
|---|---|
| 全枚数成立 | `n枚使いました` |
| 一部成立 | `2枚使えました。残り1枚は使えませんでした。` |
| 0枚成立 | 既存のエラー表示（`NO_COINS_AVAILABLE` なら枚数を取り直す） |

途中で `NO_COINS_AVAILABLE`（409）が返ったら**そこで止める。**

## 完了画面

1枚でも成立したら完了画面へ進む（履歴は置換する。完了画面から使用確認へ戻れない）。
出すのは**使用した枚数・使用したコインの通し番号・使用時刻・残り枚数**。
残り枚数は最後に成立したレスポンスの `available` をそのまま出す（フロントで引き算しない）。

## 起きてはいけないこと

- 二度押しで指定枚数より多く消費される
- 一部しか成立していないのに「n枚使いました」と出る
- 成立した分を取り消す・0枚として扱う
- `GACHA_DISABLED`（403）のときの「コインは無くなりません」が出なくなる
