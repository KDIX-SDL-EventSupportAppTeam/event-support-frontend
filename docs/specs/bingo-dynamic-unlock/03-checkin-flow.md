# チェックイン成功モーダルと評価

## モーダルの構成

チェックインが成功したら、次の順にステップを見せる。

```
1. 評価ステップ
      今回チェックインしたブースの評価を聞く
        ↓
2. チェックイン成功ステップ
      今回チェックインしたブース名 / 埋まったマス
        ↓
3. 解放演出（unlocked_positions が空でないときだけ）
        ↓
   閉じる
```

**評価を先頭に置く**のは、回収率を上げるためである。
「後で評価してね」に依存すると回収率は3割を切る（サーバー側 04-rating）。

> 2026-09-17 変更: 当初は「次のブースで前のブースを評価する」（`pending_rating`）方式だったが、
> 参加者から見て評価対象が1つずれて分かりにくいため、**チェックイン直後にそのブースを評価する**方式へ変えた。
> スキップしたブースは再提示せず、マスのタップから手動評価する。

## 評価ステップ

**星4段階（中央値なし）＋ コメント入力欄 ＋「完了」ボタン1つ。**

```
   ☆ ☆ ☆ ☆        ← 4つ。真ん中が無い
   [ コメント（任意） ]
   [      完了      ]
```

| 項目 | 仕様 |
|---|---|
| 星の数 | サーバーの `rating_scale`（既定 4）を使う。**4 をハードコードしない** |
| コメント | 任意。空欄でも送信できる |
| ボタン | **「完了」1つだけ。** 「評価を送信」「コメント送信」の2ボタンにしない |
| 星未選択で完了 | 評価を送らず次へ進む（スキップ扱い）。エラーにしない |
| 送信 | 今回の `checkin_id` に `context: 'MANUAL'` で送る（server の enum に即時評価用の値がないため） |
| 送信失敗 | **静かに握りつぶす。** チェックイン成功の表示を妨げない |

2ボタン構成をやめた理由は、評価とコメントのどちらをスキップしたか区別がつかず、
UX としても冗長なため（サーバー側 D-7）。

## 手動評価の導線

評価をスキップしたブースは再提示しない。**マスをタップして手動で評価できる導線**を残す。
このとき `context: 'MANUAL'` で送る。

## レスポンスの扱い

| フィールド | 使い方 |
|---|---|
| `filled_cell` | 埋まったマスを強調する。`null` ならカード外訪問 |
| `unlocked_positions` | **空配列でなければ解放演出を出す**（[02](02-unlock-animation.md)） |
| `new_lines` | 「ビンゴ！」の表示 |
| `pending_rating` | **使わない**（評価対象は今回の `checkin_id`） |

`unlocked`（真偽値）と `coins_earned` は**もう来ない。** 参照しているコードを直す。

## カード外訪問

`filled_cell` が `null` のとき、参加者には
**「チェックインは記録されたが、カードには載らなかった」**ことが分かるようにする。

ただし否定的に見せない。訪問自体は歓迎すべきことであり、
**評価は同じように求める**（サーバー側 D-17）。

## 起きてはいけないこと

- 評価を送っていないのにモーダルが閉じて、次のチェックインでも聞かれない
- 評価の送信失敗でチェックイン成功の表示が消える
- 星が5つ表示される
- 「評価を送信」と「コメント送信」の2ボタンが残っている
