# カードの表示

## マスの3状態

サーバーは `is_revealed` / `is_achieved` の2つの真偽値を返す。組み合わせは3通り。

| is_revealed | is_achieved | 表示 |
|---|---|---|
| false | false | **閉じたマス。** ブース名を出さない。「？」等のプレースホルダ |
| true | false | **開いているが未訪問。** ブース名とブース説明を出す。「行ってみる」導線 |
| true | true | **達成。** ブース名 + 達成マーク |

`is_revealed: false` のマスでは `booth` が `null` で来る。**フロントで補完しない。**

### `is_revealed: true` かつ `booth: null`

**割り当て可能なブースが0件だったマス**（サーバー E7）。サーバーは詰み回避のため
`is_achieved` を立てて返すので、**達成マスと同じ見た目**（スタンプ `bingo-cell-stamp.png`）で描く。

| マス内の文言 | タップ | モーダルの中身 |
|---|---|---|
| 「**すべてのブースを訪問しました**」 | **できる** | ブース名が入らない理由の説明。「回れるブースはすべて訪問済み」「このマスは訪問済みとして扱われ、ラインにも数えられる」「不具合ではない」 |

- **「ブースが決まりませんでした」とは書かない。** 全部回りきった終点であり、失敗ではない
- 文言はマス内で2〜3行になるため、スタンプを小さくして 4×4（375px 幅）で溢れないようにする
- **評価導線（星）は出さない。** `canRate` / `isRated` は `Boolean(cell.booth)` を条件にしているので、
  `booth: null` では出ない。この条件を緩めないこと

**未決**: 「全制覇」と「ブース数不足（有効ブースがマス数を下回る運営都合）」は意味が正反対だが、
サーバーが両者を区別するフィールドを返すのは
[event-support-server#150](https://github.com/KDIX-SDL-EventSupportAppTeam/event-support-server/issues/150) 以降。
**それまでは全制覇として扱う。** 出し分けは同 issue のマージ後に行う（frontend #152）。

## 表示する情報

- ブース名
- **ブース説明（`booth.description`）** — 新しく出す
- 手動コード（`manual_code`）— チェックイン導線用

**推薦理由文は出さない。** サーバーも返さない。

## 進捗表示

サーバーの `progress` をそのまま出す。フロントで数え直さない。

```
center_achieved / center_total   中央マスの達成数
revealed_cells                    見えているマスの数
achieved_cells                    達成したマスの数
lines_completed                   成立ライン数
```

**コインの枚数は表示しない。** ガチャは準備中のため
（`event-support-server/docs/specs/gacha-and-award/`）。

## 次に何をすればよいかを伝える

段階解放の狙いは「視覚的に周遊のハードルを下げる」ことである。
**参加者が今どうすればよいかが一目で分かること**を最優先にする。

| 状況 | 伝えること |
|---|---|
| 中央が0〜1マス | 「気になるブースを回ってみよう」 |
| 中央が2マス以上・外周が開いた直後 | 「新しいマスが開きました」 |
| 外周が開いている | 開いたマスのブースへの導線 |

**推薦理由の説明文は不要。** ビンゴの形式自体が「次にどう行動すればよいか」を伝える
（サーバー側 D-6）。

## 4×4 のレイアウト

`cells` は position 昇順の16件の配列で来る。CSS グリッドで4列に並べる。
**2次元配列に組み替えない。**
