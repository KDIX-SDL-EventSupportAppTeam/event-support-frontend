# 解放演出

## 何が変わるのか

**旧実装は「解放は1回きり」を前提にしている。** カードが `CENTER_ONLY` から `UNLOCKED` へ
一度だけ変わり、localStorage の単一フラグで再生済みを判定していた。

**新仕様では解放が最大3回起きる。** この前提が壊れる。
放置すると「1回目の演出しか出ない」または「毎回同じ演出が繰り返される」というバグになる。

## 解放の回数と規模

| 何回目 | きっかけ | 開くマス数 |
|---|---|---|
| 1回目 | 中央2マス目の達成 | 2マス |
| 2回目 | 中央3マス目の達成 | 4マス |
| 3回目 | 中央4マス目の達成 | 6マス |

## 再生済みの管理

**解放イベントごとに独立したフラグを持つ。**

- サーバーは `unlock_events[].pair_key`（`5-6` など6種）を返す
- 再生済みフラグのキーに `pair_key` を含める
- 単一のブール値で管理しない

```
再生済み判定 = 「この pair_key の演出をこの端末で再生したか」
```

**旧実装の単一フラグ（`shared/lib/bingoUnlockFlag.ts`）は作り直す。**

## 2つの経路

| 経路 | いつ | 何を見るか |
|---|---|---|
| **正** | チェックイン成功時 | レスポンスの `unlocked_positions`（空配列なら演出しない） |
| 副 | カード画面を開いている間 | socket の `bingo:unlocked` |

**socket は取りこぼし対策である。** スマホをポケットに入れる・別アプリを開く・電波が切れる、
といった状況で接続は簡単に切れるので、socket に依存した設計にしない。

カード取得のレスポンスにも `unlock_events` が含まれるので、
**両方の経路を逃しても、次にカードを開いたときに未再生の演出を出せる。**

## 演出の内容

**静止画のモーダルを表示し、「閉じる」ボタンと自動クローズの両方を持つこと。**
アニメーションのバーストは使わない（何が起きたのか読み取れないため。issue #148）。

| 要素 | 決まり |
|---|---|
| 画像 | `public/` の静止画1枚。`alt=""` の装飾扱いで、情報は文言に持たせる。`src` の指定は1箇所にまとめ、差し替え可能にする |
| 文言 | 「新しいマスが開きました」＋ **開いたマス数**（2マス・4マス・6マス）が伝わる1行 |
| ボタン | ラベルは**「閉じる」**。「スキップ」とは書かない（処理を飛ばすと読めてしまう） |
| ボタンの活性 | 表示直後 1.5 秒は `disabled`。**位置と大きさは前後で変えない**（`disabled` を外すだけ） |
| 自動クローズ | 3 秒後。**外さない**（操作を無期限に奪わない） |

閉じるのを遅らせても守られるものは無い。解放はチェックイン API の同一リクエスト内で
同期実行され、このモーダルが出る時点で推薦・マスの書き込み・`recommendation_scores` の記録は
すべて完了している。1.5 秒は読む時間の猶予であって、処理待ちではない。

## 起きてはいけないこと

- 同じ `pair_key` の演出が2回出る
- 1回目の演出しか出ない
- 演出中に操作が完全にブロックされる（自動クローズを外して無期限に待たせる／「閉じる」がいつまでも押せない）
- 演出が終わる前に画面を離れると、以降その解放の演出が二度と出ない
