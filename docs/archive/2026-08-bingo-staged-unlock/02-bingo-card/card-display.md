# カードの表示

## データ源

`GET /api/v1/events/:event_id/bingo/card`（[サーバー仕様](../../../../event-support-server/docs/.sdd/06-api/participant-api.md)）。
`cells` は `position` 昇順で必ず16件。行優先（row = pos/4, col = pos%4）で 4x4 に並べる。

## マスの見た目

| `state` | 表示 |
|---|---|
| `LOCKED` | **枠と「?」のみ。**ブース名は無い（そもそもサーバーが返さない） |
| `EMPTY` (CENTER) | 空きマス。「ここに次の訪問が入ります」が伝わる見た目 |
| `EMPTY` (OUTER) | 推薦されたブース名を表示。未達成 |
| `ACHIEVED` | 達成済みの見た目。ブース名を表示 |

### ロック中マスを完全非表示にしない（重要）

**枠と「?」は必ず出す。**完全に何も無いと、参加者は自分が16マスのゲームをしていることを認識できない。全体像が見えたまま解放を待つ状態にすることで、期待感の演出としても機能する。実装コストはほぼゼロ。

## 参加ボーナスマス

`source === 'SIGNUP_BONUS'` のマスには、**他のマスと視覚的に区別できるバッジ**を付ける。ラベルは「ご参加ありがとうございます」の趣旨が伝わるもの。

**★ 参加への報酬であることを明示する。抽選や推薦の結果と誤解させない。**

## 解放前のガイド

**常時表示する。**

```
あと N ブース回るとカードが広がります
```

`N = progress.visits_to_unlock`（サーバーが算出する。クライアントで数えない）。
`status === 'UNLOCKED'` になったらこの表示は消す。

**催促や煽りの文言にしない。**3件埋めずに帰るのは正常な行動である。

## コイン表示

`coins.earned` / `coins.max`（4）をそのまま表示する。**ライン数をローカルで数え直さない。**サーバーの値を正とする。

既存の `countCompletedBingoLines`（`src/shared/data/sample/bingoRandom.ts`）はサンプルモード専用として残す。

**「中央4マスが揃った = コインが増える」という表示を作らないこと。**中央2x2 はラインを構成しないため、実際には増えない。

## 更新タイミング

- チェックイン成功後、レスポンスの `filled_cell` / `coins_earned` で楽観的に反映してよい
- `unlocked === true` を受け取ったら、**演出後にカードを再取得する**
- socket.io の `bingo:unlocked` は取りこぼし対策の副経路。受け取ったらカードを再取得する（演出は二重に出さない）
